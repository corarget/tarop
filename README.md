# Tarop

Первая версия Telegram-бота с тремя виртуальными AI-консультантками, тематическими раскладами на трёх картах, историей в Cloudflare D1 и ограничением бесплатных запросов.

В этой версии нет платежей, сайта и административной панели.

## Что реализовано

- выбор одной из трёх консультанток: Мира, Алиса или Ева;
- выбор темы: отношения, работа, решение или свой вопрос;
- свободный вопрос длиной от 10 до 1000 символов;
- программный выбор трёх уникальных карт из 22 Старших арканов, включая прямое или перевёрнутое положение;
- разные стили AI-интерпретации для каждой консультантки;
- локальный mock-режим без внешнего AI API;
- живые расклады через Cloudflare Workers AI в развёрнутой бета-версии;
- OpenAI-совместимый адаптер для реального провайдера;
- история раскладов и команда её удаления;
- атомарное ограничение бесплатных раскладов (шесть на Telegram ID в развёрнутой бета-версии);
- whitelist тестовых Telegram ID;
- проверка секрета webhook и идемпотентная обработка повторных Telegram updates;
- runtime-тесты в среде Cloudflare Workers с настоящим D1 binding.

Таро в сообщениях бота прямо обозначено как символический инструмент самоанализа, а не гарантированный прогноз или профессиональная рекомендация.

## Структура

```text
src/
  db/                 D1-репозиторий, лимиты и история
  llm/                Workers AI, mock и OpenAI-совместимый адаптер
  personas/           три персонажа и их стили
  tarot/              колода и безопасный случайный выбор карт
  telegram/           типы Bot API, клиент и сценарий диалога
  app.ts              проверка и обработка webhook
  index.ts            HTTP entrypoint Worker
migrations/           SQL-миграции D1
test/                 unit и Worker runtime-тесты
docs/                  ручной чек-лист качества ответов
cloudflare.config.ts  типизированная конфигурация Cloudflare
```

## Требования

- Node.js `22.23+` или `24.22+`;
- npm;
- аккаунт Cloudflare для деплоя;
- Telegram-бот, созданный через [@BotFather](https://t.me/BotFather).

Проект использует новый Cloudflare CLI `cf` и `cloudflare.config.ts`. Конфигурация и команды соответствуют актуальному шаблону Cloudflare для новых Workers-проектов. Локальный режим использует фиксированный тестовый UUID D1 только в `--mode development`; при production deploy база provisioned отдельно.

## Локальный запуск

1. Установите зависимости:

   ```bash
   npm install
   ```

2. Создайте локальный файл секретов:

   ```bash
   cp .dev.vars.example .dev.vars
   ```

   Замените `TELEGRAM_BOT_TOKEN` и `TELEGRAM_WEBHOOK_SECRET` своими локальными значениями. Файл `.dev.vars` игнорируется Git.

3. Примените миграции к локальной D1:

   ```bash
   npm run db:migrate:local
   ```

4. Запустите Worker:

   ```bash
   npm run dev
   ```

5. Проверьте health endpoint по адресу, который напечатает CLI:

   ```bash
   curl http://localhost:5173/health
   ```

Локально по умолчанию включён `AI_MODE=mock`, поэтому внешний AI API и настоящий ключ для тестов не нужны.

## Переменные и secrets

Несекретные настройки находятся в `cloudflare.config.ts`:

| Имя                  | Значение по умолчанию                    | Назначение                                   |
| -------------------- | ---------------------------------------- | -------------------------------------------- |
| `AI_MODE`            | `mock` локально, `workers-ai` на сервере | `mock`, `workers-ai` или `openai-compatible` |
| `AI_BASE_URL`        | `https://api.openai.com/v1`              | базовый URL для `openai-compatible`          |
| `AI_MODEL`           | `gpt-4.1-mini`                           | модель для `openai-compatible`               |
| `FREE_READING_LIMIT` | `1` локально, `6` на сервере             | число бесплатных завершённых раскладов       |
| `TEST_TELEGRAM_IDS`  | пусто                                    | Telegram ID через запятую без лимита         |

Secrets объявлены через `bindings.secret()` и никогда не должны попадать в Git:

| Имя                       | Назначение                                      |
| ------------------------- | ----------------------------------------------- |
| `TELEGRAM_BOT_TOKEN`      | токен от BotFather                              |
| `TELEGRAM_WEBHOOK_SECRET` | случайная строка для заголовка Telegram webhook |
| `AI_API_KEY`              | ключ для режима `openai-compatible`             |

Сгенерировать секрет webhook можно локально:

```bash
openssl rand -hex 32
```

Не отправляйте токены и ключи в чат, issue, логи или коммиты.

## Генерация раскладов

На сервере бот использует Mistral Small через привязку Workers AI `AI`. Отдельный API-ключ для этого режима не нужен. В модель передаются вопрос, выбранные сервером карты и стиль персонажа. Если генерация завершилась ошибкой, бесплатная попытка возвращается и вопрос можно отправить повторно.

Для перехода на внешний OpenAI-совместимый API:

1. В `cloudflare.config.ts` измените:

   ```ts
   AI_MODE: bindings.text("openai-compatible");
   ```

2. Укажите `AI_BASE_URL` и `AI_MODEL` выбранного OpenAI-совместимого сервиса.
3. Добавьте реальный `AI_API_KEY` только в локальный secret-файл и при деплое.

Адаптер отправляет вопрос, выбранные сервером карты и стиль персонажа. Модель не выбирает и не заменяет карты.

## Деплой

### 1. Авторизация

```bash
npx cf auth login
```

### 2. Первый деплой и D1

`DB` объявлен как автоматически provisioned D1 binding. Первый деплой создаст недостающий ресурс:

```bash
npm run deploy -- --secrets-file .dev.vars
```

Сохраните ID созданной D1 из вывода команды или найдите его через `npx cf d1 list`. Затем примените миграции:

```bash
export D1_DATABASE_ID="replace-with-d1-id"
npm run db:migrate:remote
```

После миграции повторно выполните deploy, если первый запрос к Worker мог прийти до создания таблиц.

Для production рекомендуется держать отдельный ignored-файл secrets и передавать его через `--secrets-file`; не используйте тестовые значения из `.dev.vars.example`.

### 3. Настройка Telegram webhook

Подставьте URL Worker и держите токен/секрет только в переменных текущей оболочки:

```bash
export WORKER_URL="https://your-worker.workers.dev"
export TELEGRAM_BOT_TOKEN="replace-locally"
export TELEGRAM_WEBHOOK_SECRET="replace-locally"

curl -fsS "https://api.telegram.org/bot${TELEGRAM_BOT_TOKEN}/setWebhook" \
  --data-urlencode "url=${WORKER_URL}/telegram/webhook" \
  --data-urlencode "secret_token=${TELEGRAM_WEBHOOK_SECRET}" \
  --data-urlencode 'allowed_updates=["message","callback_query"]'
```

Проверить webhook:

```bash
curl -fsS "https://api.telegram.org/bot${TELEGRAM_BOT_TOKEN}/getWebhookInfo"
```

## Команды бота

- `/start` — приветствие и выбор консультантки;
- `/new` — начать новый расклад;
- `/history` — показать последние пять раскладов;
- `/delete_history` — удалить историю, не восстанавливая бесплатный лимит;
- `/help` — краткая справка.

## D1 и надёжность

Миграция создаёт таблицы `users`, `usage_limits`, `readings`, `messages` и `processed_updates`.

- лимит резервируется условным `UPDATE`, поэтому два одновременных запроса не получают одну и ту же бесплатную попытку;
- при ошибке AI резерв возвращается;
- карты и вопрос сохраняются до вызова AI;
- результат сохраняется до отправки в Telegram;
- повторный update не запускает вторую генерацию, а завершённый результат можно безопасно дослать после сетевого сбоя.

Для выкладки изменения схемы сначала проверяйте на локальной или отдельной staging D1. Локальные миграции не применяются к удалённой базе автоматически.
